# QA Checklist｜发布前检查

## A. 内容
- [ ] 没有为了排版擅自重写用户观点。
- [ ] 没有把文章切成过多小标题。
- [ ] 图片位置与内容有关，不是为了“隔几段插一张”。

## B. 双轴路由
- [ ] 已明确 1 个 Content Preset。
- [ ] 已明确最多 1 个 Visual Archetype。
- [ ] 没有把 Content Preset 当完整视觉模板。
- [ ] 如果用户有成熟品牌，品牌优先于默认视觉原型。
- [ ] 如果用户有当前参考图，参考图优先于默认原型。
- [ ] 如果存在园所 / 领导视觉偏好卡，已作为约束使用，但没有推翻内容逻辑。

## C. 视觉
- [ ] 同屏颜色数量克制。
- [ ] 没有每段一个卡片。
- [ ] 童趣来自低饱和色与少量素材，不是贴纸堆积。
- [ ] 正式感不是靠大量编号和边框制造。
- [ ] 真实照片仍然是主角。
- [ ] 没有复刻第三方完整模板、Logo、水印或专属插画。

## D. 微信 HTML
- [ ] 正式正文只使用 `section / span / p / table / td / strong / img`。
- [ ] 正式正文没有 `div / class / id`。
- [ ] 所有关键样式 inline。
- [ ] 所有颜色为六位 `#RRGGBB`。
- [ ] 没有 `rgba()`。
- [ ] 没有渐变。
- [ ] 没有 `background-image`。
- [ ] 没有 CSS 格子纹 / 纸张纹理。
- [ ] 没有 absolute / relative / fixed 布局依赖。
- [ ] 没有 flex / grid 关键布局。
- [ ] 双栏只使用简单 table。
- [ ] 整篇背景采用双层 section。
- [ ] 多个相邻 section 连续铺主背景色。
- [ ] 没有空 `img src`。
- [ ] 没有伪造图片 URL。

## E. 一键复制
- [ ] 复制按钮 / 调试 UI 不在正式正文中。
- [ ] ClipboardItem 只写 `text/html`。
- [ ] 正文不依赖 JavaScript 才能显示。

## F. 秀米微调
- [ ] 已给出 3–6 个具体微调位置。
- [ ] 每个位置说明当前效果 / 建议调整 / 素材来源或搜索词 / 必要性。
- [ ] 微调建议与当前 Visual Archetype 一致。
- [ ] 已说明哪些地方不建议再动。
- [ ] 没有要求用户去秀米重新从头排版。

## G. 隐私与版权
- [ ] 公共示例使用虚构园所 / 虚构人物 / 占位素材。
- [ ] 没有把其他园所 Logo、水印、专属插画直接带入模板。
- [ ] 没有把秀米 / 135 的完整第三方模板重新打包进公开仓库。
- [ ] 涉及儿童真实照片时，提醒最终发布者自行确认授权和隐私边界。

## 最后一问

如果去掉 1–2 个装饰元素，文章是否反而更清楚？

如果答案是“是”，继续做减法。
